# IdeaHub

IdeaHub — учебный проект для поиска и выбора идей программных проектов.
Каталог помогает студентам и начинающим разработчикам подобрать тему по языку
программирования, автору и доступности.

## Текущий этап разработки — ПР7

На практической работе № 7 добавлен слой реляционного хранения данных:

- база предметной области — `data/idea_hub.sqlite`;
- таблицы, ограничения и индексы создаются через `sql/schema.sql`;
- данные из JSON переносятся скриптом `db/import_json.py`;
- в `sql/queries.sql` хранятся 17 именованных SQL-запросов;
- Django-представления получают данные через стандартный модуль `sqlite3`;
- каталог, карточки идей, категории, свободные и выбранные идеи, авторы
  и статистика отображают данные из SQLite.

Доступ к данным предметной области выполняется без Django ORM. Подключение
этих таблиц к Django-моделям относится к следующим практическим работам.
Корневой `models.py` содержит обычные Python-классы предыдущих этапов.

Веб-интерфейс позволяет просматривать и искать идеи. Регистрация, авторизация,
выбор и освобождение идеи, управление контентом реализованы в сохранённой
консольной версии, работающей с JSON. Автоматической синхронизации JSON
и SQLite нет: после изменений через консоль требуется повторный импорт.

## Запуск

Требуется Python 3.10 или новее и зависимости из `requirements.txt`.
Команды выполняются из корня проекта.

```bash
python -m venv .venv
```

Активация окружения в Linux/macOS:

```bash
source .venv/bin/activate
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей, создание базы, импорт и запуск сайта:

```bash
python -m pip install -r requirements.txt
python -m db.database
python -m db.import_json
python manage.py check
python manage.py runserver
```

Откройте <http://127.0.0.1:8000/>. Импорт также создаёт схему, поэтому при первом
запуске можно выполнить только `python -m db.import_json`.
`CREATE TABLE IF NOT EXISTS` и `CREATE INDEX IF NOT EXISTS` позволяют повторно
запускать создание схемы без удаления существующих данных.

`data/idea_hub.sqlite` хранит идеи, категории и пользователей проекта.
Отдельная база `db.sqlite3` из настроек Django предназначена для встроенных
приложений Django. Команда `python manage.py migrate` создаёт их служебные
таблицы, но не заменяет создание схемы и импорт базы предметной области.

Консольная версия запускается отдельно:

```bash
python main.py
```

## Структура базы данных

Схема определена в `sql/schema.sql`. Основные сущности — категория языка
программирования, пользователь и идея проекта. Статус хранится в поле идеи.

### Таблица `categories`

| Поле | Тип | Назначение и ограничения |
| --- | --- | --- |
| `id` | `INTEGER` | Первичный ключ |
| `name` | `TEXT` | Название языка, `NOT NULL`, `UNIQUE` |

### Таблица `users`

| Поле | Тип | Назначение и ограничения |
| --- | --- | --- |
| `id` | `INTEGER` | Первичный ключ |
| `name` | `TEXT` | Имя пользователя, `NOT NULL`, `UNIQUE` |
| `password` | `TEXT` | Хеш пароля из JSON, `NOT NULL` |
| `is_admin` | `INTEGER` | Признак администратора: `0` или `1`, по умолчанию `0`, `NOT NULL` |

### Таблица `ideas`

| Поле | Тип | Назначение и ограничения |
| --- | --- | --- |
| `id` | `INTEGER` | Первичный ключ |
| `title` | `TEXT` | Название идеи, `NOT NULL` |
| `description` | `TEXT` | Описание идеи, `NOT NULL` |
| `category_id` | `INTEGER` | Внешний ключ на `categories.id`, `NOT NULL` |
| `author_id` | `INTEGER` | Внешний ключ на `users.id`, `NOT NULL` |
| `status` | `TEXT` | `не взята` или `взята`, по умолчанию `не взята`, `NOT NULL` |
| `selected_by_id` | `INTEGER` | Внешний ключ на `users.id`; `NULL` у свободной идеи |
| `created_at` | `TEXT` | Дата создания в формате `YYYY-MM-DD`, `NOT NULL` |

Одна категория объединяет несколько идей, один пользователь может быть автором
нескольких идей. У идеи один автор, одна категория и не более одного выбравшего
её пользователя.

Первичные ключи однозначно определяют записи. Внешние ключи запрещают ссылки
на отсутствующие категории и пользователей; их проверка включается через
`PRAGMA foreign_keys = ON` при каждом подключении.

Ограничения `CHECK` разрешают только предусмотренные статусы и согласуют статус
с выбором пользователя: для `не взята` поле `selected_by_id` должно быть `NULL`,
для `взята` — заполнено. Частичный уникальный индекс
`one_selected_idea_per_user` позволяет пользователю выбрать только одну идею.
Дополнительные индексы созданы по категории, автору и паре «статус — дата».

## Перенос данных из JSON

`db/import_json.py` использует существующие загрузчики из `storage.py`, проверяет
наличие файлов, уникальность идентификаторов внутри каждой сущности и формат дат.
Затем данные записываются в порядке зависимостей: категории → пользователи → идеи.
Идентификаторы и связи исходных записей сохраняются, логический признак
`is_admin` преобразуется в число `0` или `1`.

```bash
python -m db.import_json
```

Для исходного набора данных результат:

```text
Импорт завершён: categories: 5, users: 5, ideas: 4
```

Повторный импорт использует `INSERT ... ON CONFLICT(id) DO UPDATE`: обновляет
записи с теми же идентификаторами и не создаёт дубликаты. Он может перезаписать
изменения соответствующих записей в SQLite; записи, отсутствующие в JSON,
автоматически не удаляются. Запись всех трёх таблиц выполняется в одной
транзакции с откатом при ошибке.

Можно указать другой каталог источников и файл базы:

```bash
python -m db.import_json --data-dir data --database data/idea_hub.sqlite
```

Веб-приложение по умолчанию читает путь `DB_PATH` из `db/database.py`.
Создание базы по другому пути само по себе не переключает сайт на неё.

Проверка количества строк и целостности через SQLite CLI, если он установлен:

```bash
sqlite3 data/idea_hub.sqlite
```

```sql
SELECT COUNT(*) FROM categories; -- 5
SELECT COUNT(*) FROM users;      -- 5
SELECT COUNT(*) FROM ideas;      -- 4
PRAGMA integrity_check;          -- ok
PRAGMA foreign_key_check;        -- пустой результат при отсутствии нарушений
```

## SQL-запросы и страницы

Все запросы хранятся в `sql/queries.sql` в секциях `-- name: имя`.
Эти же секции загружаются модулем `db/queries.py` и выполняются приложением.
Значения пользователя передаются отдельно через параметры `?`.

| № | Имя запроса | Назначение | Где используется |
| --- | --- | --- | --- |
| 1 | `categories` | Список категорий с сортировкой | Главная, формы поиска |
| 2 | `users` | Список имён пользователей | Форма поиска по автору |
| 3 | `ideas` | Каталог с категориями, авторами и выбравшими пользователями; `JOIN`, `LIMIT`, `OFFSET` | `/ideas/` |
| 4 | `idea_detail` | Связанные данные одной идеи; `JOIN`, `WHERE` | `/ideas/<id>/` |
| 5 | `filtered_ideas` | Поиск по названию, категории, автору и статусу; сортировка и пагинация | `/ideas/` с параметрами |
| 6 | `available_ideas` | Свободные идеи с поиском по названию и категории | `/ideas/available/` |
| 7 | `selected_ideas` | Занятые идеи с именами выбравших пользователей; `JOIN`, `WHERE` | `/ideas/selected/` |
| 8 | `category_detail` | Категория по идентификатору | `/categories/<id>/` |
| 9 | `category_ideas` | Идеи выбранной категории; `JOIN`, `WHERE` | `/categories/<id>/` |
| 10 | `idea_totals` | Общее число, свободные и занятые идеи; `COUNT`, `SUM`, `MIN`, `MAX` | Главная, статистика |
| 11 | `user_totals` | Число авторов идей и пользователей с выбранной идеей; `COUNT(DISTINCT ...)` | Статистика |
| 12 | `category_statistics` | Количество идей по категориям, включая пустые; `LEFT JOIN`, `GROUP BY` | `/categories/`, статистика |
| 13 | `author_statistics` | Количество идей по авторам, включая пользователей без идей; `GROUP BY` | `/ideas/authors/`, статистика |
| 14 | `popular_categories` | Категории с числом идей не ниже порога; `GROUP BY`, `HAVING` | Статистика |
| 15 | `status_statistics` | Распределение идей по статусам; `GROUP BY`, `COUNT` | Статистика |
| 16 | `recent_ideas` | Последние идеи по дате создания; `ORDER BY`, `LIMIT` | `/` |
| 17 | `filtered_count` | Число результатов поиска для пагинации; `COUNT`, `WHERE` | `/ideas/` |

Набор покрывает требование ПР7: не менее 10 запросов и не менее двух запросов
каждого вида — списки, `WHERE`, `JOIN`, агрегатные функции и `GROUP BY`.
Результаты всех запросов используются в веб-приложении.

### Получение данных в Django

Путь обработки запроса: URL → представление → `db/queries.py` → SQL → SQLite
→ результат `sqlite3.Row` → контекст шаблона → HTML.

`db/database.py` задаёт `sqlite3.Row` как `row_factory`, поэтому поля результата
доступны по именам. Функции `fetch_all` и `fetch_one` открывают базу для чтения,
выполняют именованный запрос и закрывают соединение. `fetch_ideas` дополнительно
подготавливает вложенные данные категории, автора и выбравшего пользователя
для существующих шаблонов.

Например, представление выбранных идей в `catalog/views.py` передаёт результат
запроса в контекст шаблона:

```python
return render(request, "catalog/selected.html", {
    "ideas": fetch_ideas("selected_ideas"),
})
```

Пример параметризованного запроса из Python:

```python
from db.queries import fetch_all

rows = fetch_all("available_ideas", ("Трекер", "Трекер", 1, 1))
for row in rows:
    print(row["title"], row["category_name"])
```

В этом запросе параметры названия и категории используются по два раза:
для проверки отсутствия фильтра и для самого условия отбора.

### Проверка пользовательских сценариев

- `/` — последние три идеи, категории и общие счётчики.
- `/ideas/` — каталог по 12 идей на странице. Параметры: `q`, `category`, `author`,
  `status`, `sort`, `page`. Сортировка: `newest`, `oldest`, `title`.
- `/ideas/?category=1&sort=title` — идеи категории Python по названию.
- `/ideas/1/` — карточка идеи с категорией, автором, статусом и датой создания.
- `/ideas/available/?category=1` — свободные идеи категории Python.
- `/ideas/selected/` — выбранные идеи с именами пользователей.
- `/ideas/authors/` — пользователи и количество созданных ими идей.
- `/ideas/statistics/?minimum=2` — общие показатели, группировки по категориям,
  авторам и статусам, категории с минимум двумя идеями.
- `/categories/` и `/categories/1/` — категории со счётчиками и идеи категории.

Поиск `q` проверяет буквальное вхождение фрагмента в название через `instr`
и учитывает регистр. Для исходных данных отображаются 4 идеи: 3 свободные
и 1 выбранная; 5 категорий и 5 пользователей.

Пустые выборки сопровождаются сообщениями в шаблонах. Некорректные параметры
поиска возвращают HTTP 400, отсутствующая идея, категория или страница
пагинации — HTTP 404.

## Проверки

В активированном виртуальном окружении:

```bash
python manage.py check
pytest -v
flake8 . --extend-exclude=venv
```

Тесты проверяют прежнюю предметную логику и JSON-хранилище, схему SQLite,
ограничения и связи, повторный импорт и откат при ошибках, SQL-фильтрацию,
группировки, страницы Django, параметры поиска, пагинацию и пустые результаты.
Каждый тест использует временную базу, не изменяя демонстрационную SQLite-базу.
